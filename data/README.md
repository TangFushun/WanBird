# 内容与来源维护

`birds.json` 为图鉴数据，`sources.json` 为可引用资料目录。分类、坐标、照片和百科正文各自具有不同来源，不能互相替代。

- `content_review.status`：`draft` 表示种级正文待复核；`sourced` 表示按具体资料整理并附有段落出处，不表示鸟类专家审校。
- `summary_sources`、`anhui_sources`、各 `sections[].sources` 均引用 `sources.json` 的键；`source_ids` 按本页显示顺序列出这些键。
- 每项来源保存标题、发布机构、原文链接、发布日、本站查阅日和引用用途。未记录的日期使用 `null`，不得用文件修改时间补填。
- `iucn_evidence` 记录评级依据与评估年份。国家一级/二级保护与 IUCN 全球受威胁等级分别维护。引用旧评估或机构转述时，明确版本限制。
- 数据库入口链接仅帮助查阅，不能用来证明缺少种级出处的习性描述。基础资料暂保留待复核状态，不批量贴上“权威审核”标签。
- `dramas.json` 的 `science_sources` 对应科学知识出处；`story_note` 与 `footage_note` 分别说明故事创作和实拍素材核实状态。修改页面文字不会修改已制作的视频内容。

观测点位于 `public/static/data/occur/<id>.json`。今后下载时会另存 `<id>.meta.json`，记录真实下载时间、检索年份与坐标数量；旧数据未记录下载时间时显示“未记录”。不把坐标点数当作原始记录总数、现存个体数或完整分布。

## 皖羽踪迹：安徽省内观测记录与时间联动

页面 `/traces` 使用 `public/static/data/traces/` 下两个本地文件，不依赖在线瓦片、地图 SDK 或识别 API。

- `anhui-cities.geojson`：2026-10-29 归档自 [DataV.GeoAtlas 安徽16市边界](https://geo.datav.aliyun.com/areas_v3/bound/340000_full.json)。依据[官方坐标说明](https://help.aliyun.com/zh/datav/datav-7-0/user-guide/map-data-format-1)按 GCJ-02 使用，供科普汇总示意；区划以快照为准。
- `observations.json`（schema_version=2）：重新采集 GBIF 公开人工观测记录后，按鸟种×市×约20公里网格×年份×月份汇总。实际记录数、鸟种数、网格数、观测年份和月份完整度均保存在 `coverage`，由页面动态读取。
- `data/anhui-gbif-records.json.gz`：可离线重建的处理后记录索引，保留 GBIF ID、鸟种、年/月、原始日期、数据集、许可、市代码与网格编号，不保存精确经纬度。每个 GBIF ID 只纳入一次，同址的不同记录分别计数。
- 采集先查询中国境内、安徽及周边检索框（114.8–119.7°E、29.3–34.8°N）、1980–2026年、具有坐标且无 GBIF 地理问题的 HUMAN_OBSERVATION / PRESENT 记录。科学名先与本站国家一、二级保护鸟类匹配，再用 GBIF 物种级精确匹配获取分类编号；最终以安徽16市多边形严格裁切。检索框总数不是安徽省内总数，且本专题不代表完整名录。
- 记录按页下载，校验物种编号不变、页间检索总数稳定及记录ID完整性，拒绝将不完整分页标为完成。成功页缓存支持网络中断后恢复；采集缓存与精确坐标仅保留在被 Git 忽略的 `_tools/anhui-gbif/` 中。每个物种的检索条件、获取日期、输入 SHA-256 与纳入/排除计数写入 `audit`。
- 排除省界外记录、无效坐标/日期、跨鸟种重复ID，以及坐标不确定度明确大于20公里的记录。未提供不确定度的坐标不擅自填为零精度。缺少月份时保留未知，只进入总计，不补造月份。
- 点在 Polygon/MultiPolygon 内判定，支持孔洞；共边点按边界文件顺序唯一归属，不重复计入两市。地图的网格在省界处裁切，按市筛选时进一步裁切到市界。
- 网格为参考纬度32°的局部等距圆柱近似投影，原点114°E、29°N，步长20公里。原始坐标 WGS84 转 GCJ-02 后才与边界比较。只公开网格汇总，不在新专题内展示精确点位。
- 获取日期与观测日期分别显示。按记录ID计数不等于独立观测事件，更不等于个体数；平台覆盖、重复观测、野生状态与调查努力未逐条核验。空间图、月份图和年际曲线仅描述本次公开记录快照，不用于推断迁徙路径或种群增长。
- 点击网格后，鸟种构成、月份柱形和年份曲线使用同一选区。月份图保留当前年份范围的全年比较，年份图保留当前月份的全期比较，地市条形图保留同一鸟种/保护级别/时间条件下的全省比较；页面标明各视图范围。选择零记录月份/年份时保留选中的网格。
- 原版79为5种鸟的去重坐标点数。新版为更多鸟种的 GBIF 记录ID计数，统计单位不同，不能用两个总数计算记录增长率。原版无日期坐标仍供原有图鉴地图使用，不混入新版时间图。

更新公开记录：先运行 `python scripts/fetch_anhui_observations.py`，确认无采集错误；再运行 `python scripts/fetch_anhui_observations.py --metadata-only` 获取原始数据集标题、DOI与许可；最后运行 `python scripts/build_anhui_traces.py --refresh-records` 生成不含精确GPS的记录索引与前端汇总。保留每个上游数据集的独立许可，不统一声明 CC BY。需要新的数据快照时，应先归档并换用新的采集缓存，避免混用旧页面缓存。

若存在持续获取失败的候选鸟种，可显式追加 `--use-complete-species`，只纳入已经完整分页校验的物种；未获取物种及错误写入 `source.omitted_candidates`，页面同步披露数量。不把某物种仅获取到的部分页面冒充完整结果。下次采集成功后可重新构建以补齐遗漏。

如果网络采集被中断，可先运行 `python scripts/fetch_anhui_observations.py --finalize-cache`，重新核验已完成文件并整理清单；该步骤不访问网络，也不会将未下载完的页面纳入。再获取来源元数据并显式使用完整物种子集构建即可。

离线重建：`python scripts/build_anhui_traces.py`，读取已保存的处理后记录索引。确需更新边界时使用 `--refresh-boundary`，同步核对快照日期和来源；此命令不会更新原始 GBIF 数据。部署时一并提交处理后记录索引、两个前端静态数据文件、页面及 JS/CSS，无新增 Python 运行依赖。

检查：`node --test tests/traces.test.cjs`；`python -m unittest discover -s tests -p test_*.py`。本机有 Shapely 和原始缓存时，会独立核对每条保留记录的市界归属与网格编号；无相关依赖/缓存时跳过该交叉核验，不影响生产运行。

浏览器交互测试夹具：`python tests/traces_preview.py`（5081端口），页面明确标为“模拟数据”，用于检查跨年份、未知月份、零记录及多视图联动。该夹具不被生产应用导入，也不能作为真实数据预览。
